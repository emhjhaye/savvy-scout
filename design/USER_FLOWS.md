# Savvy Scout — Complete User Flows & Page Map

## User Roles & Key Workflows

### 1. **Sector Owners** (Mark, Kanvesh, Hammad)
- **Primary task**: Review new notices (Phase 1 triage), approve/reject with reasoning
- **Secondary task**: Review scope reads (Phase 2), approve/reject AI assessments
- **Access**: Personal queue + all opportunities in their sector

### 2. **Victoria (Bid Director)**
- **Primary task**: Review escalations only (FLAGs + owner-marked decisions)
- **Secondary task**: Make bid/no-bid decisions + enter rule corrections
- **Access**: Escalation queue + admin for rule updates

### **Stage 2: Dashboard & Queue Selection**

#### Page: `dashboard-home.html` (refine)
**For Sector Owners:**
- Header: "Your Queue — [Owner Name]"
- Overview stats: New items, Awaiting approval, On-time rate, Win rate
- Queue tabs:
  - **New (Phase 1)** — Notices awaiting Phase 1 triage
  - **In Review** — Currently open items
  - **Awaiting Approval** — Owner's decisions pending final click
  - **Pipeline** — Phase 2 approved items

**For Victoria:**
- Header: "Escalations"
- Only shows: Escalation queue (FLAGs + owner-marked items)
- Status: "Awaiting Your Decision"

**Components:**
- Sidebar navigation (persistent)
- Queue card showing item count + quick action button
- Right sidebar: Quick actions, filters

---

### **Stage 3: Phase 1 Triage (Sector Owner)**

#### Page: `notice-detail--phase1.html` (new)
**Header Section:**
- Ref (e.g., "066188")
- Title (exact from source)
- Buyer name, Source (Find a Tender / Contracts Finder)
- Indicative value (or "UNVERIFIED")

**Content Tabs:**
1. **Opportunity Details**
   - Title, Buyer, Value, CPV codes, UK stage
   - Deadline (PME, tender close, submission date if available)
   - Brief summary (first 400 chars from description)

2. **Gate Results** (auto-run, non-editable)
   - Gate 1: Sector/Owner → outcome + reasoning
   - Gate 2: Type of work → outcome + reasoning
   - Gate 3: Framework status → outcome + reasoning
   - Gate 4: Window → outcome + reasoning
   - Gate 5: CPV codes → outcome + reasoning
   - Filter 3: Scale/incumbents → outcome + reasoning
   - **Any FLAG = escalate to Victoria**
   - **Any FAIL = auto-reject**

3. **Full Notice JSON** (collapsible)
   - Raw evidence snapshot for audit trail

**Action Panel (Right sidebar):**
- Green "PASS – Approve for Phase 2" button
- Red "FAIL – Reject with reason" button
- Yellow "Victoria Decision – Mark for escalation" button
- Required: Free text reason for any decision

---

### **Stage 4: Phase 2 Scope Read (Sector Owner)**

#### Page: `notice-detail--phase2.html` (new)
**Header Section:**
- Same as Phase 1 (Ref, Title, Buyer, Value)
- Badge: "Phase 2 — AI Scope Read"

**Content Tabs:**
1. **AI Assessment** (from Claude API call)
   - **Capability Fit**: Rating (High/Med/Low) + 1-line reasoning (marked PROVISIONAL)
   - **Right to Win**: Rating (High/Med/Low) + reasoning (marked PROVISIONAL)
   - **Competitor Position**: Rating (Strong/Neutral/Weak) + reasoning (marked PROVISIONAL)
   - **Overall**: Pass/Flag/Fail recommendation + reasoning (marked PROVISIONAL)
   - **Open Questions**: Bulleted list generated by AI
   - Badge throughout: "PROVISIONAL — FOR VALIDATION"

2. **Original Details** (tabs to Phase 1 data)
3. **Gate Results** (reference only, not editable)

**Action Panel:**
- Green "ACCEPT assessment" button
- Red "REJECT — Reason?" button
- Yellow "ESCALATE to Victoria" button
- Any rejection requires free-text reason

---

### **Stage 5: Victoria Escalation Flow**

#### Page: `escalation-queue.html` (new)
**Header:**
- "Escalations" (FLAGs + owner-marked items)
- Filter: By type (FLAG / Owner-marked), By gate, By urgency

**Queue List:**
- Ref + Title
- Trigger reason (which gate, why FLAG)
- Owner (who marked it)
- Days in queue
- Status: "Awaiting your decision"

**Inline Actions:**
- "View Brief" button (opens brief in sidebar or modal)
- "Quick decision" buttons: Approve / Park / Reject (each opens reason dialog)

#### Page: `escalation-brief.html` (new)
**Ten Sections (auto-generated from `brief.py`):**
1. Opportunity Summary (title, ref, source)
2. Buyer
3. Value
4. Route to Market
5. Gate Outcomes (all gates, with reasons)
6. Provisional Ratings (from Phase 2 AI if available)
7. Competitor Picture
8. Risks (all FAG gate reasons)
9. Open Questions (AI + FLAG reasons)
10. Recommended Next Action (Victoria decision required)

**Action Panel:**
- Green "APPROVE" → Success toast, moves to APPROVED
- Orange "PARK" → Moves to PARKED, requires reason
- Red "REJECT" → Requires reason, moves to REJECTED
- All decisions logged with timestamp + Victoria's username

---

### **Stage 6: Pipeline & Tracking**

#### Page: `pipeline.html` (new)
**Pipeline View by Status:**
- Tabs: APPROVED | DOCS_DOWNLOADING | CALENDARED | ACTIVE | PARKED | REJECTED
- Each tab shows items grouped by owner/sector
- Columns: Ref, Title, Buyer, Deadline, Owner, Status, Last Updated

**Quick Actions:**
- "Download Documents" (manual task for portal-locked items)
- "View Calendar Sync Status"
- "Re-triage" (if rule changed)

---

### **Stage 7: Admin & Settings (Victoria only)**

#### Page: `admin.html` (new)
**Tabs:**

1. **Sources & Health**
   - API Toggles: Find a Tender (enabled/disabled), Contracts Finder (enabled/disabled)
   - Last sweep timestamp, next scheduled sweep
   - Health indicator: green = healthy, yellow = warnings, red = failed
   - Manual "Sweep Now" button

2. **Gate Rules**
   - Editable lists: Pass CPV codes, Inferred fit, Flag list, Fail list
   - Buyer-to-owner mapping (searchable)
   - Sector definitions
   - Version history of rule changes with date, who changed, reason

3. **Email Whitelist**
   - List of approved @bidsavvy.io recipients
   - Add/remove recipients
   - Test email button

4. **Nudge Thresholds**
   - "Flag if in queue > X days"
   - "Flag if deadline < X days"
   - "Flag if no Victoria decision by Y date"

5. **Audit Log**
   - All status changes, approvals, rejections
   - User, timestamp, reason
   - Searchable / filterable by date range, user, notice

**Status badges:**
- GREEN: PASS, APPROVED, PASS

- Sort: Deadline (ascending), Added date (newest first), Owner

- Search: By ref, By buyer name, By title keywords

## Mobile Responsiveness

- **Mobile breakpoint**: < 768px
- **Sidebar**: Collapse to icons + hamburger menu
- **Queues**: Stack single-column
- **Details pages**: Full-width with collapsible sections
- **Buttons**: Larger touch targets (minimum 44px)

---

## Color & State System

| State | Color | Usage |
|-------|-------|-------|
| **PASS** | Green (#00BFA6 / teal) | Gate pass, approval |
| **FLAG** | Orange/Amber (#FFB47A) | Attention needed |
| **FAIL** | Red (#FF4D4F) | Rejected, failed gate |
| **MAYBE** | Yellow/Amber | Uncertain, needs review |
| **PARKED** | Gray (#9AA3AD) | On hold |
| **UNVERIFIED** | Muted gray | Data not confirmed |
